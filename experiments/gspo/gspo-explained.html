01 · 先看结论

把很多 token ratio 压成一个 sequence ratio

GSPO 保留 GRPO 的组采样、reward 和 advantage，只改 policy loss：整条回答先对 token log-ratio 求平均，再取 exp，得到每条约回答唯一的 ratio。

03 · 符号与公式

GSPO 只把“逐 token 的 ratio”改成“整条序列的 ratio”

reward、group size 和 advantage 都与第 07 章同源。真正的改动发生在把 logprob 差变成 policy objective 的位置：GSPO 先对一条回答内所有 token 的 log-ratio 求平均，再取指数。

  • i组内第 i 条回答，本 run 有 4 条。
  • yi,t第 i 条回答的第 t 个 completion token。
  • Δi,tlog πcurrent − log πold，当前策略相对采样策略的 log-ratio。
  • si整条回答唯一的 sequence ratio，也叫几何平均 ratio。
  • Ai组内 reward 去均值后的 sequence advantage，一条回答共享一个值。
  • δlow, δhigh相对 1.0 的裁剪偏移，本 run 是 0.0003 和 0.0004。
si = exp( (1 / Ti) Σt=1..Ti Δi,t )
先在 log 空间平均，再 exp。Ti 是这条回答的 completion token 数。
LGSPO,i = −min(siAi, clip(si, 1−δlow, 1+δhigh) Ai)
每条回答只有一个 ratio、一次 clip、一个标量 objective。
裁剪区间是 [0.9997, 1.0004]

3e−4 / 4e−4 是相对 1.0 的偏移，不是 ratio 本身的 0.0003–0.0004。把它们当成绝对区间会把整个公式读反。

04 · 唯一改动

从逐 token 裁剪，变成整条回答裁剪

token-level (02/07):
  ratio_t = exp(current_t - old_t)
  clip 每个 token

sequence-level (08):
  log_ratio_i = mean_t(current_t - old_t)
  ratio_i     = exp(log_ratio_i)
  clip 整条回答一次

在 log 空间先平均，可以避免概率连乘溢出，也让 20 token 和 200 token 的回答落在相近的 ratio 尺度上。裁剪边界 3e-4 / 4e-4 是相对 1.0 的偏移，不是 0.0003 的绝对 ratio。

05 · 完整训练链路

从 4 条回答到 1 个 sequence objective

GSM8K同一道题
→
4 条 rollout0/1 reward
→
组内 advantager − mean
→
sequence ratiomean log-ratio → exp
→
clip oncebackward + step
for each non-degenerate group:
    rewards = [0, 1, 0, 1]
    advantages = [r - mean(rewards) for r in rewards]  # [-.5,+.5,-.5,+.5]

    for completion, advantage in zip(group, advantages):
        log_ratio_t = current_logprob[t] - old_logprob[t]   # one per token
        log_ratio_i = mean(log_ratio_t)                      # one per answer
        ratio_i = exp(log_ratio_i)
        clipped_i = clamp(ratio_i, 0.9997, 1.0004)
        objective_i = min(ratio_i * advantage, clipped_i * advantage)
        loss_i = -objective_i
        loss_i.backward()

    optimizer.step()

注意 advantage 仍是一条回答一个标量，GSPO 改的是 importance ratio 的聚合粒度。每个 token 的当前 logprob 和 old logprob 仍要逐位置算出，否则无法得到序列平均。

07 · 真实数据手算

四条长度不同的回答，各自只得到一个 ratio

step 4 的 advantage 先手算

  1. rewards 为 [0,1,0,1]，均值是 0.5。
  2. 用组内去均值（本 run 的 GSPO 路径）：0−0.5=−0.5，1−0.5=+0.5。
  3. 因此 advantage 为 [−0.5,+0.5,−0.5,+0.5]；GSPO 不再除以标准差。

假设四条回答的平均 log-ratio 都是 0.0002

  1. si=exp(0.0002)≈1.00020002，落在 [0.9997,1.0004] 内。
  2. 错误回答的 objective：1.0002×(−0.5)≈−0.5001；正确回答约 +0.5001。
  3. 取负号后，错误回答的 loss 约 +0.5001，正确回答约 −0.5001。这是公式层面的示意，真实 loss 还取决于每条回答各自的 ratio。

这里不是要你把 0.0002 当成日志值，而是看清：长度 69、108、76、110 都不会改变 ratio 的数量级，因为它们各自先做了 token 平均。

09 · 为什么区间这么小

序列 ratio 的变化会被整条回答累积

token ratio

每个位置独立

一个 token 的 ratio 从 1.0 变到 1.5，影响的是那个位置。

sequence ratio

先平均 log 差

整条序列共享一个 ratio；同样的策略偏移更容易被看成一次全局变化，所以边界必须收紧。

若每个 token 的 log ratio 都是 ln(1.5):
  20 token 的 log 均值仍是 ln(1.5) → ratio 1.5
  200 token 也一样 → ratio 1.5
  但直接连乘会得到 1.5^200，数值完全不可用

这就是 log 空间平均的意义：不是让长回答“多算几次”，而是让不同长度共享同一个可比较尺度。

11 · 常见疑问

GSPO 最容易被问到的六件事

为什么要在 log 空间求平均，而不是把 token 概率直接相乘？

概率相乘等于 logprob 相加，长回答会得到极端小或极端大的数，容易下溢或溢出。先对 log-ratio 求平均再 exp，数值稳定，而且不同长度落在同一尺度。

sequence ratio 是普通算术平均 ratio 吗？

不是。它是 token ratio 的几何平均：exp(mean(log ratio))。如果所有 token ratio 相同，几何平均就等于它；否则它更关注 log 空间的平均变化。

为什么 clip 边界这么小？

整条序列共享一个 ratio，少量 token 的偏移会累积成全局变化；为了保守更新，论文把相对 1.0 的允许偏移设得很小。边界不是 ratio 的绝对值区间。

为什么 loss 4.16e−05 还能算一次更新？

loss 接近 0 只说明这个 batch 上新旧策略很接近、objective 很小；只要 backward 和 optimizer.step 执行了，参数就可能变化。是否“有效”要看是否有真实更新，不只看 loss 大小。

这个 run 能证明 GSPO 比 GRPO 好吗？

不能。没有同预算 GRPO 对照、没有能力评测、只有 3 次有效更新和一个随机种子；它验证的是 sequence-level loss 和工程路径。

为什么 skipped group 还会写进 samples？

为了保留完整实验证据：即使没有 backward，也能回查模型生成了什么、reward 为什么全对或全错。这样 23 次 attempt 和 3 次 effective update 才能对得上。
