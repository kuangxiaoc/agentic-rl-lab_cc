01 · 先看结论

把很多 token ratio 压成一个 sequence ratio

GSPO 保留 GRPO 的组采样、reward 和 advantage，只改 policy loss：整条回答先对 token log-ratio 求平均，再取 exp，得到每条约回答唯一的 ratio。

3 / 23最终 run 的有效更新 / 总尝试。20 个组因全对或全错被跳过，真正进入 backward 的只有 3 次。
这次没有能力评测

本地 run 只验证 sequence-level loss、裁剪和 backward。它没有 AIME25，也没有 base 与 checkpoint 的准确率对比。

03 · 唯一改动

从逐 token 裁剪，变成整条回答裁剪

token-level (02/07):
  ratio_t = exp(current_t - old_t)
  clip 每个 token

sequence-level (08):
  log_ratio_i = mean_t(current_t - old_t)
  ratio_i     = exp(log_ratio_i)
  clip 整条回答一次

在 log 空间先平均，可以避免概率连乘溢出，也让 20 token 和 200 token 的回答落在相近的 ratio 尺度上。裁剪边界 3e-4 / 4e-4 是相对 1.0 的偏移，不是 0.0003 的绝对 ratio。

06 · 为什么区间这么小

序列 ratio 的变化会被整条回答累积

token ratio

每个位置独立

一个 token 的 ratio 从 1.0 变到 1.5，影响的是那个位置。

sequence ratio

先平均 log 差

整条序列共享一个 ratio；同样的策略偏移更容易被看成一次全局变化，所以边界必须收紧。

若每个 token 的 log ratio 都是 ln(1.5):
  20 token 的 log 均值仍是 ln(1.5) → ratio 1.5
  200 token 也一样 → ratio 1.5
  但直接连乘会得到 1.5^200，数值完全不可用

这就是 log 空间平均的意义：不是让长回答“多算几次”，而是让不同长度共享同一个可比较尺度。
