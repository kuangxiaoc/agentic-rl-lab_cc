01 · 先看结论

同一个模型，换一份 prompt，就变成了老师

OPSD 的 Teacher 不是更大的模型，而是同一个 Qwen3-4B base：Student 只看题目，Teacher 额外看到参考解。Student 先采样，两个 prompt 再对同一条 completion 计算 logprob。

4次真实 optimizer step，每次 1 条 256-token completion。KL 从 0.152 波动到 0.504，再回到 0.235。
这一章的重点是“特权上下文”

Teacher 的能力来自它看到了 Student 看不到的参考解，而不是来自第二份更大的参数。

03 · 符号与公式

同一份参数，两个条件分布

OPSD 的关键不是“两个模型”，而是“同一个模型看到两份不同上下文”。Student 只看到 problem；Teacher 看到 problem 和 reference solution。Student 采样一条 completion 后，两个条件分布都对这条完全相同的 token 序列打分。

  • xproblem，Student 可见的题目。
  • creference solution，Teacher 的 privileged context。
  • y1..TStudent 从 p(·|x) 采样出的 completion。
  • pSp(yt | x, y<t)，Student 的条件分布。
  • pTp(yt | x, c, y<t)，Teacher 的条件分布。
  • β把 reverse KL 差变成 advantage 的系数，本 run 为 1。
rtKL = log pS(yt | x, y<t) − log pT(yt | x, c, y<t)
两个模型参数相同，但条件上下文不同；这是 OPSD 和普通 OPD 的核心区别。
At = −β · rtKL
Student 比 Teacher 更偏爱当前 token 时，advantage 为负，训练压低它；反之提高。
ρt = exp(log πθ(yt) − log πold(yt)),   LIS = −meant(ρtAt)
本 run 也使用 importance_sampling；KL 差提供 advantage，ratio 只校正采样策略与当前策略的变化。
为什么 Teacher 不重新生成

如果 Teacher 另采一条 y'，就不存在同一个 yt 上的两个 logprob，无法逐 token 对齐。OPSD 的“判卷”是给 Student 的原卷打分，不是让 Teacher 重写答案。

04 · 两个 prompt

差别只在参考解，不在模型参数

Student prompt

只有题目

Problem: …
Please reason step by step …

Teacher prompt

题目 + 参考解

Problem: …
Reference Solution Begin … End
请理解上面的推理，但不要直接复制。

Teacher 不会重新生成答案。它拿到的是 teacher_prompt + student_completion，只对 Student 已经写出的 token 做一次 forward。

06 · 完整训练链路

四次 step，每次都从采样到更新完整走一遍

problemStudent prompt
→
sample1 × 256 token
→
two scoresStudent / Teacher
→
token KLadvantage = −KL
→
updateStudent QLoRA
for step in range(4):
    y = student.generate(problem, n=1, max_new_tokens=256)
    old_logp = student.logprob(problem + y)          # Student prompt
    teacher_logp = teacher.logprob(problem + solution + y)

    kl_t = old_logp - teacher_logp
    advantage_t = -1.0 * kl_t
    loss = -(exp(current_logp - old_logp) * advantage_t).mean()
    loss.backward()
    optimizer.step()                                  # only Student adapter

    save history + sample

Teacher 是冻结的 base 副本；Student 是带 QLoRA 的同一份 base。Teacher 的 prompt 多了参考解，但 completion 仍是 Student 已经写出的同一串 token。

08 · 真实数据手算

38.958 的序列 KL，怎么变成每 token 0.152？

step 0 的二次方程题

  1. Student 的序列 logprob 是 −44.1254，Teacher 是 −83.0837。
  2. 差值：−44.1254 − (−83.0837) = +38.9583。
  3. completion 长度是 256，所以每 token 均值：38.9583 / 256 ≈ 0.15218。
  4. β=1，逐 token advantage 总和为 −38.9583；训练会整体压低这些 Student 更偏爱的前缀。

这不是“Teacher 知道正确答案，所以每个 token 都对”。Teacher 只提供相对偏好；它可能因为参考解而改变对某些推理步骤的信心，也可能对 Student 的写法不认同。

为什么四步 KL 会上下跳？

  1. step 0 到 step 3 的均值分别是 0.1522, 0.3620, 0.5043, 0.2348。
  2. 每个 step 只有一道题、一条 completion，题目和采样前缀都变了。
  3. 因此这组曲线主要反映样本差异，不足以估计策略是否收敛。

10 · 信号形态

稠密反馈，但不是无限可靠的老师

优点

每个 token 都有梯度

不用等整条回答结束，也不用组内出现对错混合。

优点

不需要第二个模型

Teacher 只是同一份 base 加参考解，显存和部署都更轻。

风险

参考解不等于正确

Teacher 看到 solution 后仍可能给出错误偏好；KL 只表示差异，不表示真理。

11 · 结果边界

这次 run 没有证明数学能力提高

可以确认：同一 base 的双 prompt、Student 采样、Teacher 同轨迹打分、reverse KL advantage、4 次 optimizer step 都真实发生。不能确认：AIME 或任何独立数学 benchmark 提升，也不能确认 full-vocabulary JSD 的效果。

全部 completion 都是 256 token

4 个 step 的平均 completion 长度都是 256，正好撞上上限。这次比较的是推理前缀上的 token 偏好，不是完整解答。

12 · 常见疑问

OPSD 的六个常见误解

OPSD 的 Teacher 为什么不需要更大的模型？

Teacher 的优势来自额外的参考解上下文，而不是参数规模。同一份 4B base 在“题目 + 参考解”条件下，能给出和“只看题目”不同的 token 分布；这个差异就是训练信号。

为什么 Teacher 不能重新生成一条答案？

因为 KL 要逐 token 对齐。Teacher 必须对 Student 已经写出的同一个 yt 打分；重新生成会换掉轨迹，无法把两个分布的差值落到同一位置。

这是 full-vocabulary JSD 吗？

不是。本地实现只在 Student 实际采样的 token 上计算 logprob 差，是 sampled-token reverse KL 估计；没有遍历完整词表，也没有 JSD 的对称项。

为什么参考解不是“正确答案”，也能当老师？

因为 OPSD 学的是条件分布变化，不是把参考解当唯一标签。Teacher 看到 solution 后可能更偏向某些推理路径；它仍然是概率模型，不是硬编码的判卷器。

为什么 KL 下降不能直接等同于数学能力提高？

KL 只衡量 Student 与 Teacher 的分布差。Student 可以变得更像 Teacher，但如果 Teacher 本身有偏差，或者训练只覆盖 256-token 前缀，独立数学正确率不一定提高。

四步实验能得出什么结论？

只能确认双 prompt、同轨迹打分、KL advantage、QLoRA backward 和产物保存都真实发生。不能确认数学 benchmark 提升，也不能证明 OPSD 优于其他蒸馏方法。
