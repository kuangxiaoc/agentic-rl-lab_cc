03 · 符号与公式

DAPO 没有 value model，它用同组答案互相比较

GRPO 类方法对每道题采样一组回答，用组内 reward 的均值和标准差构造 advantage。DAPO 保留这条主链，并改变采样过滤与 clip 边界。先把符号翻译成动作：

  • Ggroup size。本 run 每道题采 4 条回答。
  • ri第 i 条回答的 reward。本 run 是 ±1 的正确性奖励。
  • μ, σ这 4 条回答 reward 的均值和样本标准差。
  • Ai组内标准化 advantage；整条回答共享同一个值。
  • ρt训练时当前策略与采样时旧策略在第 t 个 token 上的概率比。
  • εlow, εhighratio 的下界和上界；本 run 为 0.8 和 1.28。
Ai = (ri − μ) / (σ + εstd)
本 run 的代码使用样本标准差（分母 n−1），εstd=1e−4。全组同分时 advantage 为 0。
ρt = exp(log πθ(yt) − log πold(yt))
ρ=1 表示该 token 的概率没变；大于 1 表示当前策略更偏爱它。
LPPO = −meant[ min(ρtAt, clip(ρt, 0.8, 1.28) At) ]
本 run 关闭 token-level loss，所以仍按每条回答内部 token 的 mean 计算，再对样本平均。
为什么全对/全错组没有信号

如果四条 reward 都是 1 或都是 −1，μ 与每条 ri 相同，分子为 0，所有 advantage 都为 0。即使生成了四条回答，梯度也没有“谁更好”的信息。

attempts = 0
effective = 0
while effective < 3 and attempts < 32:
    completions = student.generate(question, n=4)
    rewards = [score(text, gold) for text in completions]

    if all_correct(rewards) or all_wrong(rewards):
        save skipped sample
        continue                    # Dynamic Sampling

    advantages = (rewards - mean) / (std + 1e-4)
    for completion, advantage in zip(completions, advantages):
        loss = ppo_loss(current_logprobs, old_logprobs, advantage,
                        clip_low=.8, clip_high=1.28)
        loss.backward()
    optimizer.step()
    effective += 1

skip 的组也会写进 samples.jsonl 和 history，所以 27 个 attempt 都能回查。它们没有进入 optimizer，但采样、解码、答案抽取和 reward 计算已经花掉了。

07 · 真实数据手算

2 对 2 错，为什么 advantage 是 ±0.866 而不是 ±1？

step 4 的四条 reward

  1. reward 为 [−1, +1, −1, +1]，均值 μ=0。
  2. 样本方差：((−1)2+12+(−1)2+12) / (4−1) = 4/3。
  3. 样本标准差：σ=√(4/3)≈1.1547。
  4. 错误回答：(−1−0)/(1.1547+0.0001)≈−0.86595；正确回答为 +0.86595。

如果只看 reward，正负号已经足够；除以标准差后，不同题目即使 reward 幅度不同，也会被拉到相近的梯度尺度。ε 很小，这里几乎不影响结果。

3 对 1 错时，advantage 又变了吗？

  1. reward 为 [+1,−1,+1,+1]，均值是 0.5。
  2. 样本标准差约 1.0，错误回答 advantage 约 −1.4999，正确回答约 +0.49995。
  3. 这说明“少数派”会被推得比多数派更远；组内比例改变，单个样本的梯度权重也改变。

09 · Clip-Higher

上界从 1.2 放宽到 1.28

PPO  : clamp(ratio, 0.8, 1.2)
DAPO : clamp(ratio, 0.8, 1.28)

ratio = exp(current_logprob - old_logprob)

正 advantage 且 ratio 已经超过 1.2 的 token，在 PPO 里继续提高概率不会带来更多 objective；Clip-Higher 把这段空间放宽。这次 run 记录的是配置，不是 ratio 分布，所以不能从页面推断实际有多少 token 被 1.28 截住。

12 · 常见疑问

DAPO 页面的六个常见问题

为什么 correct_rate=0.5 时 mean reward 是 0，而不是 0.5？

因为 reward 是 ±1，不是 0/1。两条 +1、两条 −1 相加为 0，均值就是 0。correct_rate 是正确条数比例，和 reward 的数值尺度不是同一个量。

Dynamic Sampling 丢掉全对组，为什么还叫“采样”？

因为模型已经实际生成了那 4 条回答；Dynamic Sampling 只是在计算 advantage 前做过滤，不进入 backward。它节省的是优化器计算，不是生成成本。

Clip-Higher 为什么只放宽上界？

DAPO 想让正 advantage 的 token 有更大上升空间，避免过早被 1.2 截住；下界仍保留 0.8 抑制过度下降。这个 run 只记录配置，没有保存 ratio 分布，所以不能推断实际有多少 token 触及 1.28。

为什么这次不叫完整 DAPO 复现？

因为 token_level_loss=false 且 overlong_cache=0。Token Mean 和 Soft Overlong Punishment 都没有真正参与，只验证了 Dynamic Sampling + Clip-Higher 的组合。

effective step 和原始 step 为什么不同？

原始 step 是第几次 attempt，包括被跳过的组；effective step 是真正执行 optimizer.step 的次数。本 run 的 3 次更新发生在原始 step 4、22、26。

为什么 3 次有效更新不能说明 DAPO 有效？

没有同预算 GRPO 对照、没有能力评测、没有多种子；而且 3 次更新太少。它证明的是过滤和更新路径真实发生，不是算法优劣。
