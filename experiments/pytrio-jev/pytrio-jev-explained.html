01 · 先看结论

它不是 RL，而是一次极窄的监督

第 04 章把“回答一道题”改成“在一次 forward 里同时做五个固定选项判断”。每个字段只在 decision marker 前一个位置计算 loss，推理时也只读候选符号的 logits。

34.4%250 个决策中答对 86 个。训练 loss 明显下降，但这只是 50 条测试记录的局部结果。
这一章最值得记住的实验事实

训练最后一步的 marker accuracy 是 60%，但测试集总体只有 34.4%。单条记录的 batch loss 很小，不等于模型已经学会稳定的决策规则。

03 · 真实训练记录

loss 从 18.04 降下来，但不是平滑下降

每步只有一条记录，所以曲线会被单条样本的字段数量、长度和难度强烈影响。下面挑了几个代表性 step，不把噪声当趋势。

为什么曲线会抖

这不是常规的大 batch 训练。每一步只更新一条记录，marker accuracy 是该记录内几个字段的比例。它的主要作用是确认 marker 对齐和梯度链路，不是估计泛化能力。

06 · 机制

标签只落在 marker 前一个位置

input:  ... "action": "decision" ...
labels: ...          ↑ 只在这里填答案 token
                        其余位置 = -100

eval:
  logits[marker - 1]
      ↓ index_select(合法候选符号)
      ↓ softmax
  prediction = argmax

这就是“决策模型”和普通 SFT 的差别。普通 SFT 要模型写完整答案；这里只要求它在固定位置从有限候选里选一个。所有字段共享 state，但答案不出现在输入中，因此字段之间不会看到彼此的标签。

07 · 结果边界

这张图能说明什么，不能说明什么

可以说明

机制跑通

marker 对齐、masked cross entropy、候选 softmax、LoRA 保存和评测回读都产生了可复核记录。

不能说明

业务可用

50 条测试记录不足以支撑生产路由结论；置信度也未校准，不能直接拿阈值放行。

不要把 34.4% 和原版五项 Jevbench 平均分混在一起

这次本地 run 只使用 typed-decisions 的 train/test，没有 ToolACE 和 Jevbench 全套评测，也没有温度校准。它是一个机制实验，不是论文表格的等价复现。
