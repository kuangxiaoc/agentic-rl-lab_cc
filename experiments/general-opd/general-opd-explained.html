02 · 实验设计

Student 和 Teacher 必须共享兼容 tokenizer。OPD 比较的是同一个 token id 在两个模型下的 logprob；词表不一致，差值就没有意义。

03 · 符号与公式

OPD 比较的是“同一串 token，两个模型各觉得多自然”

这里的 logprob 不是一个百分数，而是模型给某个 token 的对数概率。它通常是负数，越接近 0 越自信。OPD 不比较最终答案，也不让 Teacher 重新生成；它沿着 Student 已经写出的轨迹，逐个 token 比较两个模型的偏好。

  • x题目 prompt，Student 和 Teacher 使用同一份输入。
  • y1..TStudent 自回归采样出的完整 token 序列，T=256。
  • πS(yt)Student 在看到 x,y<t 后给当前 token 的概率。
  • πT(yt)Teacher 在完全相同的 token 前缀下给当前 token 的概率。
  • rtKLtoken 级 reverse KL 估计：log πS − log πT。
  • β蒸馏强度。本 run 的 kl_penalty_coef=1。
rtKL = log πS(yt | x, y<t) − log πT(yt | x, y<t)
同一个 token、同一个上下文，只比较两个模型的 log 概率。
At = −β · rtKL
Student 更偏爱时 rKL>0，advantage 为负，训练压低这个 token；Teacher 更偏爱时相反。
ρt = exp(log πθ(yt) − log πold(yt)),   LIS = −meant(ρtAt)
本 run 使用 importance_sampling，没有 clip。ρ 衡量训练时策略相对采样策略的变化；它和 OPD 的 KL 差不是同一个量。
这里的 reverse KL 是采样估计

完整 reverse KL 要在 Student 的整个词表分布上求期望；本地实现只在 Student 实际采出的 256 个 token 上求平均。单 token 的样本差值可以为负，日志里的 batch 均值也不保证非负；本 run 恰好全为正。

advantage_t  = -beta * reverse_kl_t

Student 更偏爱 → KL 为正 → advantage 为负 → 压低该 token
Teacher 更偏爱 → KL 为负 → advantage 为正 → 提高该 token
05 · 完整训练链路

一次 step 里，谁生成、谁打分、谁更新

题目DeepMath prompt
→
Student rollout2 × 256 token
→
保存 old logprob采样时的策略
→
Teacher forward同一轨迹逐 token
→
IS update只更新 Student LoRA
for step in range(15):
    completions, old_logprobs = student.generate(prompt, n=2, max_new_tokens=256)
    teacher_logprobs = teacher.score(prompt + completion)

    reverse_kl = student_logprob - teacher_logprob
    advantage = -1.0 * reverse_kl
    ratio = exp(current_logprob - old_logprob)
    loss = -(ratio * advantage).mean()    # importance_sampling

    loss.backward()
    optimizer.step()       # 只更新 Student 的 QLoRA 参数
    save history + samples

Teacher 的参数始终冻结，也不会因为这次训练获得新知识。这里所谓“老师”是一个固定的概率分布；训练做的是让 Student 在这条 Student 自己走出的轨迹上，逐渐改变对各个 token 的偏好。

07 · 真实数据手算

把一条 256-token 轨迹拆成一个标量

step 0 · answer 0

  1. Student 的序列 logprob 总和是 −73.6834；Teacher 是 −248.4076。
  2. 两者相减：−73.6834 − (−248.4076) = +174.7241，正好是日志的 reverse_kl_sum。
  3. 除以 256 个 token：174.7241 / 256 ≈ 0.6825，正好是日志的每 token KL 均值。
  4. β=1 时，这 256 个 token 的 advantage 总和是 −174.7241；平均每个 token 的 advantage 约为 −0.6825。

正号说明 Student 比 Teacher 更偏爱这条轨迹。因为训练目标是最小化 loss，负 advantage 会降低这些 token 的概率；但“降低”不是把整条回答删掉，而是逐 token 调整。

为什么整条序列的 KL 很大，但每 token 只是 0.68？

256 个 token 的差值会累加，序列总和自然放大；每 token 的均值才是更容易跨长度比较的尺度。不能拿 174.7 直接和别的 128-token 样本比较，也不能把 0.68 解释成“68% 的错误率”。

09 · 训练信号

OPD 的 advantage 是 token 级、稠密的

GRPO

整条回答一个 reward

答对/答错只在序列级别出现，组内全对或全错就没有信号。

OPD

每个 token 都有差值

不需要标准答案，也不需要等最终 reward；Teacher 的偏好直接变成 token advantage。

代价

Teacher 必须可靠

Teacher 对轨迹不自信时，KL 会很大；它不一定代表“Teacher 更正确”。

11 · 常见疑问

读 OPD 时最容易混的几个问题

Teacher 为什么不能自己重新生成一条答案？

因为 OPD 比较的是同一条 token 轨迹上的分布差。如果 Teacher 自己生成，token 序列就变了，log pS(yt) 和 log pT(yt) 不再对应同一个 yt，KL 差也无法逐位置对齐。

Student 和 Teacher 的词表为什么必须兼容？

KL 是按 token id 和上下文算的；同一个 token 在两个 tokenizer 下可能被切成不同片段，logprob 就不可比。这个实现还会主动做 tokenizer 兼容性探针，失败就拒绝运行。

KL 上升是不是训练失败了？

不一定。KL 只衡量两个策略差异；它可能因为题目变难、Student 探索到 Teacher 不喜欢的轨迹而上升。要判断训练效果，需要独立评测、长度分布和多种子，而不是要求 15 步 KL 单调下降。

为什么全部 completion 都是 256 token？

因为生成长度上限就是 256，模型没有提前生成 EOS。日志里的均值恰好等于上限，意味着这次比较只覆盖推理前缀，很多回答还没有写完最终结论。

这里的 loss 和 reverse KL 为什么几乎相等？

在 β=1、采样策略与当前策略足够接近时，importance ratio 接近 1，loss 近似为负 advantage 的均值，也就是 reverse KL 均值。两者接近是配置和数值上的结果，不是通用等式。

它和普通知识蒸馏有什么区别？

普通蒸馏通常在固定数据集上匹配 Teacher 的完整分布；OPD 先让 Student 自己采样，再只对 Student 实际访问到的 token 打分，因此训练数据随 Student 当前策略变化，属于 on-policy distillation。
