01 · 先看结论

它验证了 OPD 的 token 对齐，没有验证数学能力

Student 先自己写，Teacher 不重新生成，只对同一条 completion 逐 token 打分。15 个 step 都产生了真实 optimizer update，但 reverse KL 在 0.23–0.91 之间波动，没有单调下降。

30条 completion 进入训练。15 steps × 每步 2 条，没有退化组过滤，也没有外部 API。
最终 run 的 KL

第一步 0.6469，最后一步 0.7366，15 步均值 0.5823。这组曲线更像“机制持续运行”，而不是“student 稳定追上 teacher”。

02 · 实验设计

1.7B Student，4B Teacher，同一套 tokenizer

项目最终 run它意味着什么
StudentQwen/Qwen3-1.7B + fresh QLoRA只训练 adapter
TeacherQwen/Qwen3-4B-Instruct-2507，4-bit 冻结只做 forward，不更新
数据DeepMath-103K 的一个 parquet 分片只取 question，不用标准答案
采样group size 2，max new tokens 256同一题两条 on-policy 轨迹
训练15 steps，batch size 1每步 2 条 completion

Student 和 Teacher 必须共享兼容 tokenizer。OPD 比较的是同一个 token id 在两个模型下的 logprob；词表不一致，差值就没有意义。

03 · 数据流

先采样，再让 Teacher 沿原轨迹打分

DeepMath 题目prompt only
→
Student 采样2 条 completion
→
Teacher forward同一个 prompt + completion
→
reverse KLstudent − teacher
→
IS updateadvantage = −β · KL
reverse_kl_t = log p_student(token_t) - log p_teacher(token_t)
advantage_t  = -beta * reverse_kl_t

Student 更偏爱 → KL 为正 → advantage 为负 → 压低该 token
Teacher 更偏爱 → KL 为负 → advantage 为正 → 提高该 token

第 0 步的题目关于条件收敛级数。两条 completion 都被截在 256 token。这里看的是 token logprob 总和，不是最终答案对错。

“We are given that the series … is conditionally convergent …”

两条回答都在解释题意，还没有写到最终结论。Teacher 对这条 Student 轨迹给出更低的总概率，于是这些 token 的 advantage 为负，训练会压低它们的概率。

全部 completion 都是 256 token

15 个 step 的 completion_tokens_mean 都等于 256，正好撞上上限。这次实验看到的是“推理前缀的蒸馏”，不是完整解答的蒸馏。

短程 15 步、每步只有 2 条 completion，单个 step 的 KL 很容易被题目难度和采样内容改变。更合理的读法是看整体范围、长度是否坍缩、loss 是否异常，而不是期待一条平滑下降线。

06 · 训练信号

OPD 的 advantage 是 token 级、稠密的

GRPO

整条回答一个 reward

答对/答错只在序列级别出现，组内全对或全错就没有信号。

OPD

每个 token 都有差值

不需要标准答案，也不需要等最终 reward；Teacher 的偏好直接变成 token advantage。

代价

Teacher 必须可靠

Teacher 对轨迹不自信时，KL 会很大；它不一定代表“Teacher 更正确”。

07 · 结果边界

这次 run 能说明什么

可以说明

链路是真实的

Student 采样、旧 logprob、Teacher 同轨迹 forward、token 对齐、advantage 和 backward 都发生了。

不能说明

数学变好了

这次没有独立数学评测，也没有多随机种子；15 步不足以证明能力提升。
